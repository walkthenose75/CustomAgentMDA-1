End-to-end deployment

Deploy the Agent Sidecar to a new environment

A complete, click-by-click walkthrough: register the browser identity in Azure, prepare the Copilot Studio agent, import the reusable AgentSidecarCore solution (which includes the Code App), connect its data, and drive the in-app setup wizard — with a live worksheet that fills your own values into every step.

Copilot Studio steps: GA as of 10 Jul 2026

Overview

What you are deploying and in what order.

The Agent Sidecar is a persistent, context-aware chat pane that appears on Model-driven App forms and talks to a published Copilot Studio agent as the signed-in user. It is delivered as one solution plus a small amount of per-environment identity you supply:

AgentSidecarCore solutionOne unmanaged solution carrying everything: Dataverse tables, option sets, runtime web resources, the token-broker plugin, and the Code App itself. Importing it deploys the app too — no separate pac code push needed.
ConnectionsThe per-environment connection(s) the app's data references resolve to. Established/mapped in the maker portal at import time.
Per-environment identityAn Entra SPA app registration + a published Copilot Studio agent, wired up in the setup wizard.
The order matters
Do the Azure registration and Copilot Studio agent first. The only identifier you paste into the wizard is the app registration's client ID. The running Code App supplies the tenant and environment IDs, then discovers compatible published agents and their harnesses automatically.
No developer tooling required to deploy
Because the Code App travels inside the solution, an administrator can stand this up entirely from make.powerapps.com with just the solution .zip — no Node.js, no PAC CLI, no source repository, no pac code push.

1 Microsoft Entra app registration

Create a single-tenant, browser (SPA) client so the side pane can call Copilot Studio on behalf of the signed-in user.

  1. Open the Entra admin center. Go to entra.microsoft.com ↗, confirm the correct tenant, then open Identity › Applications › App registrations and choose New registration.
  2. Register the browser client.
    • Name: Agent Sidecar Side Pane (add an environment suffix like - Prod).
    • Supported account types: Accounts in this organizational directory only (single tenant).
    • Redirect URI: choose platform Single-page application (SPA) and paste your computed URI:
      …
    • Select Register.
    Why SPA?
    The pane is browser-hosted, so it uses authorization-code flow with PKCE. Do not register it as a confidential "Web" application.
  3. Record the two IDs. On Overview, copy the Application (client) ID and Directory (tenant) ID into the worksheet. Treat them as configuration identifiers, not passwords.
  4. Confirm authentication settings. Open Manage › Authentication.
    • Confirm the SPA platform exists with your redirect URI.
    • Leave Access tokens and ID tokens (implicit grant) cleared.
    • Under Advanced settings, set Allow public client flows = Yes.
    • Save.
  5. Add the delegated Copilot Studio permission. Open Manage › API permissions › Add a permission.
    • Choose APIs my organization uses and search Power Platform API.
    • Select Delegated permissions.
    • Expand CopilotStudio and check CopilotStudio.Copilots.Invoke.
    • Select Add permissions.
    Can't find "Power Platform API"?
    It may not be provisioned in your tenant yet. An admin can add the Power Platform API service principal by running az ad sp create --id 8578e004-a5c6-46e7-913e-12f58912df43 once, then retry.
  6. Grant admin consent. On API permissions, select Grant admin consent for <tenant> and confirm. The permission status must read Granted.
Do not create a client secret
Leave Certificates & secrets empty. A browser cannot safely hold a secret; this client relies on PKCE and short-lived delegated tokens only.

2 Copilot Studio agent

Prepare a published custom agent in the same environment as the Code App. The administration app discovers compatible agents and detects their harness automatically.

Compatibility note — GitHub Copilot harness support is experimental
Standard-harness connectivity uses the documented Agents SDK route. GitHub Copilot harness connectivity currently uses the /copilotstudio/agenticruntime/3p/ route, which Microsoft has not documented as a stable production contract. Validate that route in your environment before relying on it for production workloads.
  1. Open or create the agent. Go to copilotstudio.microsoft.com ↗, confirm you are in the target environment (top-right environment picker), and open (or create) the agent the sidecar will surface.
  2. Require Microsoft authentication. Open Settings › Security › Authentication and select Authenticate with Microsoft (Entra ID). This is what makes the agent honor the signed-in user's permissions.
  3. Publish the agent. Select Publish (top-right). The sidecar only binds to a published agent.
  4. Keep the agent in the target environment. The wizard intentionally lists only compatible published custom agents in the environment where the Code App is running. Microsoft-managed system agents are hidden.
  5. Share the agent. From the agent overview, share chat access with the intended users (or an Entra security group). Grounding (e.g. SharePoint knowledge) stays scoped to each signed-in user.

3 Import the AgentSidecarCore solution

One import brings the Dataverse tables, option sets, runtime web resources, token-broker plugin, and the Code App. This is the unmanaged AgentSidecarCore.zip that already contains the app.

Option A — Maker portal (recommended)

  1. Open Solutions. Go to make.powerapps.com ↗, select the target environment (top-right), then Solutions in the left nav.
  2. Import. Choose Import solution › Browse, select AgentSidecarCore.zip, then Next and Import. Wait for the success banner.

Option B — PAC CLI

bash
# Authenticate to the target environment
pac auth create --environment https://<your-org>.crm.dynamics.com

# Import the unmanaged Core solution
pac solution import --path ./AgentSidecarCore.zip \
  --environment https://<your-org>.crm.dynamics.com \
  --publish-changes
What lands in the environment
Tables maftagsc_sidecarconfiguration & maftagsc_targetbinding, the health/validation option sets, the runtime web resources (agentSidePane.html/.js, agentGuideLibrary.svg, authRedirect.html), the token-broker plugin, and the Agent Sidecar Code App itself — so no separate app deployment is needed.
Import the .zip as-is — don't unpack it
Code apps don't support the Solution Packager or Git source integration (per Microsoft's ALM guidance). Import the exported .zip directly through the maker portal or pac solution import; do not run pac solution unpack/pack on it, or the Code App component can be dropped.
Token-broker secure configuration
After import, the token-broker plugin step needs its per-environment secure configuration set (tenant + client details). Run your environment's set_token_broker_secure_config step, or configure the plugin step's secure config, before first use.

4 Code App & connections

The app arrived with the solution in Phase 3. Confirm it, connect its data, and open it — all in the maker portal.

  1. Confirm the app imported. In make.powerapps.com ↗ open Solutions › Agent Sidecar Core and confirm the Agent Sidecar app is listed (type App), or find it under Apps.
  2. Establish the app's connection(s). Code apps resolve their data through connection references per environment. On first import (or first play) you are prompted to create/select the connection(s) the app uses (e.g. the Dataverse connection). Create them in make.powerapps.com › Connections if they don't exist, then map each connection reference in the solution to a connection.
    Where to map
    Open the solution › the Connection references component(s), or use the import wizard's connection step (and Power Platform Pipelines preflight if you promote that way). Until every connection reference is mapped, the app opens but its data calls fail.
  3. Open the app. Play it from Apps (or the solution) and sign in. You should land on the portfolio screen, recognized as a System Administrator, with zero configured sidecars.

Developer / CI alternative (optional)

Only if you have the source repo
Administrators deploying from the solution do not need this. Developers updating the app (or wiring a pipeline) can build and push a new version directly:
bash
pac auth create --environment https://<your-org>.crm.dynamics.com
npm install
npm run build
pac code push -s AgentSidecarCore

5 Sidecar setup wizard

Five steps: Application → Tables → Agent → Identity → Review. Select New sidecar on the portfolio to begin.

Step 1 — Application

Pick the Model-driven App that will host the sidecar. Eligible apps in the environment are discovered automatically; each card shows the count of eligible tables. If an app is missing, paste its App ID in the manual fallback and select Resolve App ID.

Step 2 — Tables

The wizard lists the app's eligible tables with their friendly names and the number of active main forms each has. Enable the tables the sidecar should appear on. The configuration summary on the right tracks your choices.

Step 3 — Agent

Select the published Copilot Studio agent from Phase 2:

  • Choose a compatible published custom agent from the list.
  • The app reads the current environment ID from Power Apps context.
  • The app reads the schema name and harness metadata from Dataverse, then constructs the correct Standard or GitHub Copilot runtime URL.

Step 4 — Identity & pane

Configure delegated identity and pane behavior. All required fields must be valid GUIDs where noted:

FieldValue
Configuration namee.g. Sales Assistant (defaults from the app name)
Pane titleShown at the top of the side pane
Tenant IDDetected automatically from the signed-in Power Apps context (read-only)
Public Client Application ID… (the only identifier you paste; the wizard links to Entra App registrations)
Pane widthe.g. 420
Target Binding solutionAuto-suggested, e.g. <App>SidecarBinding
Redirect URI (read-only)… — must match the one registered in Azure
Redirect URI must match exactly
The wizard displays the redirect URI it expects. It must be identical to the SPA redirect URI you registered in Phase 1, or sign-in will fail with a redirect mismatch.

Step 5 — Review & deploy

The review screen previews the exact impact — it creates/reuses the Target Binding solution and lists how many tables and active main forms will be bound, references the existing agent (no agent is created), and notes automatic rollback. Nothing changes until you select "Deploy sidecar."

Deploy performs live form changes
Selecting Deploy sidecar adds the sidecar's OnLoad handler to the selected forms in the live environment. Review the impact first. Rollback removes only the sidecar-owned handlers and preserves unrelated form XML.

6 Validate & lifecycle

After deploying, use the portfolio controls to keep the sidecar healthy.

Validate / health

Checks configuration, that each bound form still carries the sidecar handler, delegated identity presence, and the agent reference.

Drift & reconcile

Detects when a live form's metadata diverges from the approved binding and re-applies the owned handler.

Disable / re-enable

Turns the sidecar off without removing configuration, then back on.

Uninstall

Removes only the sidecar-owned handlers, deletes the bindings/configuration, and removes the scoped Target Binding solution it created.

Verify end-to-end

  1. Open the host Model-driven App and a bound record form. The collapsed sidecar icon appears in the side pane.
  2. Open it, sign in when prompted, and send a message. The agent responds with context for the current screen and record.
  3. Navigate to another bound record — the context updates automatically on the next message.

? Troubleshooting

The most common setup snags and their fixes.

SymptomCause & fix
Sign-in fails with a redirect URI mismatchThe Azure SPA redirect URI doesn't exactly match the wizard's. Re-copy the computed URI (…) into Entra › Authentication.
Agent doesn't appear in Step 3The agent must be a published custom agent in the same environment as the Code App and use a compatible Standard or GitHub Copilot harness. Publish or republish it, then reload the administration app.
"Consent required" / token errorsAdmin consent for CopilotStudio.Copilots.Invoke was not granted. Re-grant in Entra › API permissions.
Pane loads but no answer / 401 from agentToken-broker plugin secure configuration not set for this environment, or the user lacks chat access to the agent. Set the secure config and share the agent.
App shows no eligible apps/tablesConfirm the AgentSidecarCore solution imported successfully (it contains the app + tables) and that the app's connection reference(s) are mapped. The app reads live Dataverse metadata as the signed-in user, who needs System Administrator/Customizer rights.
App opens but every data call failsA connection reference is unmapped. In the solution, open Connection references and map each to a connection in this environment.
Deploy fails resolving a solution/componentConfirm the publisher prefix (maftagsc) matches the imported solution and that you have System Administrator rights.
